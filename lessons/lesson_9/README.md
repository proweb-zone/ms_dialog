# Домашнее задание "Сервис счетчиков"

### Что было реализовано

Я разработал сервис счетчиков который хранит в себе кол-во непрочитанных сообщений. Для повышения отказоустойчивости - данные решил сохранять в RedisDB и в оперативной памяти сервиса. Такой подход позволяет избавиться от транспортных (сетевых) издержек, и убережет нас от сбоя сервиса Redis.

 ### Паттерн SAGA

 Ни для кого не секрет, что в микросервисной архитектуре для обеспечания консистености данных в разных микросервисах - используется паттерн SAGA.

 Данный паттерн был реализован в бизнес логике микросервиса ms_dialog при прочтении (получении) всех сообщений пользователя

 ### Алгоритм работы

 1) Клиент запрашивает к прочтению все сообщения своего друга
 2) Делаем запрос в RedisDb и предоставляем пользователю данные
 3) Обнуляем счетчик сервиса Counter после того как получили сообщения пользователя
 4) Делаем запрос в БД PostgreSql для постановки флага true/false поля READ (все прочтенные сообщения ставим значение true поле read)
 5) Если изменение данных в Postgresql прошли с ошибкой, то возращаем счетчик в прежнее положение (тем самым достигается консистентность данных)

## Развертывание

Открываем терминал на нашем сервере и в cli выполняем команды согласно инструкции.

1) Скачиваем 3 репозитория (otus, ms_dialog, event-getaway)

```
git clone https://github.com/proweb-zone/event-getaway.git

git clone https://github.com/proweb-zone/otus_social_network.git

git clone https://github.com/proweb-zone/ms_dialog.git
```
2) Переходим в проект event-getaway и запускаем docker контейнер

```
cd /my_path/event-getaway/
docker compose up -d
```
2) Переходим в проект otus_social_network и запускаем docker контейнер и делаем миграцию БД

```
#  переходим в проект
cd /my_path/event-getaway/

# поднимаем docker
docker compose up -d

# проводим миграцию БД
docker exec -it ms-dialog make migration-up
```
3) Переходим в проект ms_dialog и запускаем docker контейнер и делаем миграцию БД

```
#  переходим в проект
cd /my_path/ms_dialog/

# поднимаем docker
docker compose up -d

# проводим миграцию БД
docker exec -it app_socnet make migration-up
```

#  Как проверить работу паттерна SAGA

Все запросы необходимо делать в Postman

1) Зарегистрируйте двух пользователей
2) Добавьте друг друга в друзья
3) Отправьте друг другу несколько сообщений
4) Получите диалог сообщений своего друга
(пример запроса без ошибки БД)
http://localhost:3002/v2/dialog/2/list/false

Я в запрос добавить тестовый параметр, который имитирует ошибку БД
(пример запроса с ошибкой БД)
http://localhost:3002/v2/dialog/2/list/true

После которого PostgreSql вернет ошибку и счетчик сервиса Counter вернет исходное значение счетчика
